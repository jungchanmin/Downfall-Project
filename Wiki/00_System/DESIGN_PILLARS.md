# Downfall Design Pillars

## 1. Purpose

본 문서는 Downfall의 핵심 플레이 경험을 정의한다.

Project Canon이:

> Downfall은 무엇인가?

를 정의한다면,

본 문서는:

> Downfall을 플레이했을 때 무엇이 중요하게 느껴져야 하는가?

를 정의한다.

본 문서는 세부 시스템 공식, 수치, 데이터 또는 구현 알고리즘을 소유하지 않는다.

---

# 2. Pillar 1 — 관계의 누적과 변질

Downfall에서 생존자는 단순한 전투원이나 자원 슬롯이 아니다.

플레이어와 NPC, 그리고 NPC 상호 간의 관계는 25일 동안 발생하는 선택과 사건을 통해 누적되고 변화해야 한다.

관계는 항상 긍정적인 방향으로 성장하지 않는다.

다음과 같은 방향으로 변화할 수 있다.

- 신뢰
- 협력
- 친밀
- 애착
- 의존
- 경쟁
- 질투
- 불신
- 적대
- 집착
- 배신
- 붕괴

중요한 것은 특정 관계 단계 자체가 아니라,

> 플레이어가 이전에 내린 선택과 함께 보낸 시간이 이후의 장면과 판단에 의미 있는 흔적을 남기는 것

이다.

관계 시스템, 기억 구조와 구체적인 상태 전이는 별도 시스템 문서가 소유한다.

---

# 3. Pillar 2 — 매 회차 달라지는 25일

Downfall의 세계 기본 원리와 25일이라는 캠페인 구조는 고정된다.

그러나 그 안에서 플레이어가 겪는 생존 과정은 반복 플레이마다 달라져야 한다.

변동 가능한 요소에는 다음과 같은 영역이 포함될 수 있다.

- 초기 생존자 구성
- 동료 합류 과정
- 관계 궤적
- 사건
- 탐색 결과
- 괴물 조우
- 세력 접촉
- 자원 상황
- 캠페인 중 발생하는 위기

목적은 단순한 Randomization이 아니다.

같은 25일을 다시 플레이하더라도:

> 누구와 살아남았는가,
> 어떤 사건을 겪었는가,
> 무엇을 잃었는가

가 달라져 새로운 이야기가 형성되어야 한다.

구체적인 Random Table, Spawn Rule, Event Weight와 날짜별 확률은 하위 시스템이 소유한다.

---

# 4. Pillar 3 — 생존 압박과 불확실성

Downfall의 선택에는 항상 비용과 불확실성이 존재해야 한다.

플레이어는 모든 문제를 완벽하게 해결할 수 없다.

다음과 같은 자원이 서로 경쟁할 수 있다.

- 시간
- 인력
- 안전
- 물자
- 관계
- 신체적 상태
- 정신적 안정

좋은 선택이 항상 좋은 결과만 만드는 것도 아니며,

위험을 피하는 행동이 다른 위험을 만들 수 있다.

플레이어 경험의 핵심은:

> 최적의 정답을 찾는 것

보다

> 불완전한 정보와 제한된 자원으로 무엇을 감수할지 결정하는 것

에 가깝다.

공포는 단순한 충격 연출보다 이러한 불확실성과 손실 가능성에서 발생해야 한다.

---

# 5. Pillar 4 — 씬 중심 내러티브

Downfall의 이야기는 긴 설명보다 플레이 중 발생하는 장면을 통해 전달되는 것을 우선한다.

세계관과 캐릭터 변화는 가능한 한:

- 사건
- 행동
- 반응
- 대화
- 선택
- 결과

를 통해 체험되어야 한다.

하나의 장면은 단독으로 소비되는 텍스트가 아니라 이전 플레이 상태와 이후 플레이에 연결되는 사건이어야 한다.

대표적인 흐름은 다음과 같다.

```text
상황
↓
장면
↓
인물 반응
↓
플레이어 개입
↓
선택 / 판정
↓
결과
↓
상태 변화
↓
후속 가능성
```

이는 필수 구현 포맷이 아니라 Downfall 내러티브의 디자인 원칙이다.

이벤트 스키마와 실제 Trigger 구조는 Event System이 소유한다.

---

# 6. Optional Pillar — Adult Content Module

성인 콘텐츠는 Downfall에서 사용할 수 있는 중요한 확장 디자인 영역이다.

그러나 Core 게임의 존재 조건은 아니다.

원칙은 다음과 같다.

```text
Core Downfall
= 독립적으로 완전한 게임

Adult Module
= Core 경험을 확장하는 선택형 모듈
```

성인 콘텐츠는 단순한 독립 보상 장면보다 다음 Core 경험과 연결될 수 있다.

- 관계 변화
- 공포
- 위험
- 변질
- 선택의 대가
- 캐릭터 서사

하지만 Core 시스템이 Adult Module의 존재를 전제로 설계되어서는 안 된다.

성인 콘텐츠의 구체적인:

- 시스템
- 상태
- 기술
- 이벤트
- 묘사 규칙
- 데이터

는 Optional Module 문서가 소유한다.

---

# 7. Pillar Interaction

각 Pillar는 독립적으로 존재하지 않는다.

Downfall의 이상적인 플레이 경험은 다음과 같은 연결에서 발생한다.

```text
생존 압박
↓
어려운 선택
↓
관계 변화
↓
새로운 장면
↓
다음 생존 판단 변화
```

그리고 이러한 과정이 25일 동안 누적된다.

따라서 시스템은 가능한 한 단독 미니게임으로 존재하기보다 다른 Pillar와 의미 있게 연결되는 것을 우선한다.

---

# 8. Design Priority

두 디자인 목표가 충돌할 경우 기본적인 플레이 경험 우선순위는 다음과 같다.

1. 관계와 선택의 누적 결과
2. 생존 판단과 회차별 변동성
3. 공포와 불확실성
4. 장면과 캐릭터의 밀도
5. 전투 및 자원 최적화

Optional Module은 Core 우선순위를 침해하지 않는 범위에서 이를 확장한다.

이 순서는 절대적인 밸런스 공식이 아니라 디자인 판단을 위한 기준이다.

---

# 9. Anti-Pillars

Downfall은 다음 방향으로 발전하는 것을 기본적으로 지양한다.

## Perfect Solution Game

모든 문제를 올바른 선택 하나로 해결할 수 있는 구조.

---

## Pure Combat Optimization Game

캐릭터와 관계가 전투 효율을 위한 숫자로만 축소되는 구조.

---

## Static Narrative

회차와 상태가 달라도 동일한 장면과 반응이 반복되는 구조.

---

## Consequence-Free Choice

선택은 많지만 이후 플레이에 의미 있는 흔적이 남지 않는 구조.

---

## Mandatory Optional Module Dependency

선택형 Module이 없으면 Core 시스템이 정상적으로 작동하지 않는 구조.

---

# 10. Design Test

새로운 시스템이나 콘텐츠를 제안할 때 다음 질문을 사용할 수 있다.

1. 이것이 플레이어에게 의미 있는 선택을 만드는가?
2. 이전 선택이나 관계가 여기에 영향을 줄 수 있는가?
3. 이후 플레이 상태에 흔적을 남기는가?
4. 반복 플레이에서 다른 상황을 만들 수 있는가?
5. 생존 압박 또는 불확실성과 연결되는가?
6. 캐릭터나 세계를 장면을 통해 보여주는가?
7. 단순히 시스템 수를 늘리는 기능은 아닌가?

모든 항목을 충족해야 하는 것은 아니다.

하지만 어떤 Pillar에도 기여하지 않는 기능은 추가할 이유를 재검토한다.

---

# 11. Ownership Boundaries

본 문서는 다음을 소유하지 않는다.

- 관계 수치 및 공식
- NPC 기억 구조
- Event Trigger
- Random Weight
- Day Type 확률
- Combat 공식
- Resource 수치
- Adult Module 세부 규칙
- Dialogue 생성 규칙
- Narrative Template

이들은 각각의 System Contract, Data 또는 Content 문서가 소유한다.

---

# 12. Stability Rule

다음 변경은 일반적으로 Design Pillars 변경을 요구하지 않는다.

- 특정 전투 공식 변경
- NPC 능력치 조정
- 이벤트 추가
- 괴물 추가
- UI 변경
- 아이템 추가
- 밸런스 패치

반대로 다음과 같은 변경은 Design Pillars 재검토가 필요하다.

- 관계가 게임의 핵심에서 제거됨
- 25일이 사실상 선형 고정 스토리가 됨
- 생존 자원 압박이 제거됨
- 선택이 이후 상태에 영향을 주지 않음
- 장면 중심 진행에서 완전히 다른 내러티브 구조로 전환됨
- Optional Module이 Core 필수 의존성으로 변경됨

---

# 13. Final Design Statement

Downfall의 핵심 경험은

> 제한된 25일 동안 불확실한 상황에서 생존 결정을 내리고,
> 그 결정들이 사람과 관계를 변화시키며,
> 변화한 관계와 기억이 다시 다음 선택과 장면을 바꾸는 과정

에서 만들어진다.

시스템은 이 순환을 강화하기 위해 존재한다.
